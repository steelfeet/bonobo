# Переменные окружения

Лучшая практика гласит, что переменные должны передаваться в графы через переменные окружения. Это важно для того, чтобы держать чувствительные данные вне кода — например, токен API или имя пользователя и пароль, используемые для доступа к базе данных. Этот подход не только более безопасен, но также делает графы более гибкими, позволяя настраивать их для различных окружений и контекстов. Важно отметить, что переменные окружения — это также средство, с помощью которого аргументы могут передаваться в графы.

> **Примечание**
>
> Этот документ касается использования ваших собственных настроек и значений конфигурации. Если вы ищете встроенные настройки bonobo, которые также можно настраивать с помощью переменных окружения, пожалуйста, ознакомьтесь с [/reference/settings](../reference/settings.md).

## Передача / Установка переменных окружения

Установка переменных окружения для использования вашими графами может выполняться различными способами, и выбор используемого способа может зависеть от контекста. Возможно, самый непосредственный и простой способ установить/переопределить переменную для данного графа — просто использовать необязательный аргумент ``--env`` при запуске bonobo из оболочки (bash, командная строка и т.д.). ``--env`` (или ``-e`` для краткости) должен затем сопровождаться именем переменной и значением, используя синтаксис ``VAR_NAME=VAR_VALUE``. Несколько переменных окружения можно передать, используя несколько флагов ``--env`` / ``-e`` (т.е. ``bonobo run --env FIZZ=buzz ...`` и ``bonobo run --env FIZZ=buzz --env Foo=bar ...``). Кроме того, в bash вы также можете устанавливать переменные окружения, перечисляя те, которые вы хотите установить, перед командой `bonobo run`, разделяя пары ключ-значение пробелом (т.е. ``FIZZ=buzz bonobo run ...`` или ``FIZZ=buzz FOO=bar bonobo run ...``). Кроме того, bonobo может извлекать переменные окружения из локальных файлов '.env' вместо того, чтобы передавать каждую пару ключ-значение индивидуально во время выполнения. Важно отметить, что при установке переменных окружения соблюдается строгий "порядок приоритета", поэтому рекомендуется прочитать и понять порядок, указанный ниже, чтобы предотвратить

Порядок приоритета — от низшего к высшему, при этом высший "побеждает", если установлен:

1. Значения по умолчанию
   ``os.getenv("VARNAME", default_value)``
   Пользователь/автор/создатель графа отвечает за установку этих значений.

2. Значения ``--default-env-file``
   Укажите файл для чтения значений env по умолчанию. Каждая переменная env в файле используется, если переменная ещё не имеет соответствующего значения, установленного в системном окружении (системные переменные env не перезаписываются).

3. Значения ``--default-env``
   Работает как #2, но значения ``NAME=var`` по умолчанию передаются индивидуально, с одной парой ``key=value`` для каждого флага ``--default-env``, а не собираются из указанного файла.

4. Значения системного окружения
   Переменные env, уже установленные на системном уровне. Стоит отметить, что переданные переменные env через ``NAME=value bonobo run ...`` попадают сюда в порядке приоритета.

5. Значения ``--env-file``
   Переменные env, указанные здесь, устанавливаются так же, как в #2, но эти значения имеют приоритет над значениями, установленными на системном уровне.

6. Значения ``--env``
   Переменные env, установленные с использованием флага ``--env`` / ``-e``, работают как #3, но имеют приоритет над всеми остальными переменными env.

## Примеры

Приведённые ниже примеры демонстрируют установку одной или нескольких переменных с использованием обоих этих методов:

```bash
# Использование одной переменной окружения через флаг --env или --default-env:
bonobo run csvsanitizer --env SECRET_TOKEN=secret123
bonobo run csvsanitizer --default-env SECRET_TOKEN=secret123

# Использование нескольких переменных окружения через флаги -e (env) и --default-env:
bonobo run csvsanitizer -e SRC_FILE=inventory.txt -e DST_FILE=inventory_processed.csv
bonobo run csvsanitizer --default-env SRC_FILE=inventory.txt --default-env DST_FILE=inventory_processed.csv

# Использование одной переменной окружения встроенным образом (только для оболочек типа bash):
SECRET_TOKEN=secret123 bonobo run csvsanitizer

# Использование нескольких переменных окружения встроенным образом (только для оболочек типа bash):
SRC_FILE=inventory.txt DST_FILE=inventory_processed.csv bonobo run csvsanitizer

# Использование env-файла для значений env по умолчанию:
bonobo run csvsanitizer --default-env-file .env

# Использование env-файла для значений env:
bonobo run csvsanitizer --env-file '.env.private'
```

## Структура ENV-файла

Структура файла для env-файлов невероятно проста. Единственный текст в файле должен быть парами `NAME=value` с одной парой на строку, как показано ниже.

```text
# .env

DB_USER='bonobo'
DB_PASS='cicero'
```

## Доступ к переменным окружения из контекста графа

Переменные окружения, установленные ли глобально или только для области действия графа, могут быть доступны с использованием любых обычных средств. Важно отметить, что установлены ли переменные окружения глобально для системы или только для контекста графа, bonobo обращается к переменным окружения одинаковым образом. В примере ниже пользователь базы данных и пароль доступны через функцию ``getenv`` модуля ``os`` и используются для получения данных из базы данных.

```python
import os

import bonobo
from bonobo.config import use


DB_USER = os.getenv('DB_USER')
DB_PASS = os.getenv('DB_PASS')


@use('database')
def extract(database):
    with database.connect(DB_USER, DB_PASS) as conn:
        yield from conn.query_all()


graph = bonobo.Graph(
    extract,
    bonobo.PrettyPrinter(),
)
```
