# Сервисы и зависимости

Вам захочется использовать внешние системы в ваших преобразованиях, включая базы данных, HTTP API, другие веб-сервисы, файловые системы и т.д.

Жёсткое кодирование этих сервисов — хороший первый шаг, но по мере роста вашей кодовой базы этот подход довольно быстро покажет свои ограничения.

* Жёстко закодированные и тесно связанные зависимости делают ваши преобразования сложными для тестирования и повторного использования.
* Обработка данных на вашем ноутбуке — это отлично, но возможность сделать это на разных целевых системах (или этапах), в разных окружениях более реалистична. Вы захотите настроить другую базу данных на промежуточном окружении, предпроизводственном окружении или производственной системе. Возможно, у вас есть похожие системы для разных клиентов и вы хотите выбрать систему во время выполнения и т.д.

> **Предупреждение**
>
> Этот документ сейчас проверяется на правильность.

## Определение сервисных зависимостей

Чтобы решить эту проблему, мы вводим лёгкую систему внедрения зависимостей. Она позволяет определять **именованные зависимости** в ваших преобразованиях и предоставлять реализацию во время выполнения.

Для преобразований на основе функций вы можете использовать декоратор :func:`bonobo.config.use`, чтобы отметить зависимости. Вы всё ещё сможете вызвать его вручную, предоставив реализацию самостоятельно, но в контексте выполнения bonobo она будет разрешена и внедрена автоматически, пока вы предоставили реализацию исполнителю (более об этом ниже).

```python
from bonobo.config import use

@use('orders_database')
def select_all(database):
    yield from database.query('SELECT * FROM foo;')
```

Для преобразований на основе классов вы можете использовать :class:`bonobo.config.Service`, специальный дескриптор (и подкласс :class:`bonobo.config.Option`), который будет хранить имена сервисов и действовать как маркер для разрешения экземпляров сервисов во время выполнения.

```python
from bonobo.config import Configurable, Service

class JoinDatabaseCategories(Configurable):
    database = Service('orders_database')

    def __call__(self, database, row):
        return {
            **row,
            'category': database.get_category_name_for_sku(row['sku'])
        }
```

Оба приведённых выше примера кода сообщают bonobo, что ваше преобразование ожидает сервис с именем "orders_database", который будет внедрён в ваши вызовы под именем параметра "database".

### Предоставление реализаций во время выполнения

Bonobo ожидает, что вы предоставите словарь всех реализаций сервисов, требуемых вашим графом.

```python
import bonobo

graph = bonobo.graph(...)

def get_services():
    return {
        'orders_database': my_database_service,
    }

if __name__ == '__main__':
    bonobo.run(graph, services=get_services())
```

> **Примечание**
>
> Словарь или словареподобный именованный аргумент "services" может быть передан методу API :func:`bonobo.run`. Часть "словареподобный" здесь является реальным ключевым словом. Bonobo — это не библиотека DIC, и не станет ею. Таким образом, предоставленная реализация довольно базовая и бесфункциональная. Вы можете использовать гораздо более вовлечённые библиотеки вместо предоставленной заглушки, и пока она реализует словареподобный интерфейс, система будет использовать её.

Интерфейс командной строки будет искать сервисы в двух разных местах:

* Функция `get_services()`, присутствующая на том же уровне, что и определение вашего графа.
* Функция `get_services()` в файле `_services.py` в том же каталоге, что и файл вашего графа, позволяя повторно использовать те же реализации сервисов для более чем одного графа.

### Решение проблем параллелизма

Если сервис не может использоваться более чем одним потоком одновременно, либо потому, что он просто не потокобезопасен, либо потому, что требует тщательно упорядочивать вызовы (API, которые включают одноразовые числа, или работают с результатами, возвращёнными предыдущими вызовами, обычно являются хорошими кандидатами), вы можете использовать контекстный процессор :class:`bonobo.config.Exclusive`, чтобы заблокировать использование зависимости на время контекстного менеджера (оператора `with`).

```python
from bonobo.config import Exclusive

def t1(api):
    with Exclusive(api):
        api.first_call()
        api.second_call()
        # ... и т.д.
        api.last_call()
```
