Природа компонентов и то, как данные перетекают от одного к другому, может быть немного сложной. Надеемся, что их должно быть очень легко написать с несколькими подсказками.

## Чистые преобразования

Одно "сообщение" (экземпляр :class:`bonobo.Bag`) может пройти через несколько компонентов одновременно. Чтобы убедиться, что ваш код безопасен, можно :func:`copy.copy()` каждое сообщение на каждом входе преобразования, но это довольно дорого, особенно потому, что это может не понадобиться.

Вместо этого мы выбрали противоположный подход: копии никогда не создаются, вместо этого вы не должны изменять на месте входные данные вашего компонента перед тем, как выдать их, что в основном означает, что вы хотите воссоздать словари и списки перед выдачей, если их значения изменились.

Числовые значения, строки и кортежи неизменяемы в Python, поэтому изменение переменной одного из этих типов уже вернёт другой экземпляр.

Примеры будут показаны с операторами `return`, конечно, вы можете сделать то же самое с операторами `yield` в генераторах.

### Числа

В Python числа неизменяемы. Поэтому вы не можете ошибиться с числами. Всё следующее верно.

```python
def do_your_number_thing(n):
    return n

def do_your_number_thing(n):
    return n + 1

def do_your_number_thing(n):
    # верно, но плохой стиль
    n += 1
    return n
```

То же самое верно и с другими числовыми типами, так что не стесняйтесь.

### Кортежи

Кортежи неизменяемы, поэтому вы ничем не рискуете.

```python
def do_your_tuple_thing(t):
    return ('foo', ) + t

def do_your_tuple_thing(t):
    return t + ('bar', )

def do_your_tuple_thing(t):
    # верно, но плохой стиль
    t += ('baaaz', )
    return t
```

### Строки

Вы знаете, как это делать, строки тоже неизменяемы.

```python
def do_your_str_thing(t):
    return 'foo ' + t + ' bar'

def do_your_str_thing(t):
    return ' '.join(('foo', t, 'bar', ))

def do_your_str_thing(t):
    return 'foo {} bar'.format(t)
```

Вы можете, если используете Python 3.6+, использовать `f-strings <https://docs.python.org/3/reference/lexical_analysis.html#f-strings>`_, но основные библиотеки bonobo не будут использовать их, чтобы оставаться совместимыми с 3.5.

### Словари

Итак, теперь становится интересно. Словари изменяемы. Это означает, что вы можете испортить всё, если не будете осторожны.

Например, выполнение следующего может (и будет) вызвать неожиданные проблемы:

```python
def mutate_my_dict_like_crazy(d):
    # Плохо! Не делайте этого!
    d.update({
        'foo': compute_something()
    })
    # Всё ещё плохо! Не изменяйте словарь!
    d['bar'] = compute_anotherthing()
    return d
```

Проблема легко понять: поскольку **Bonobo** не будет создавать копии вашего словаря, тот же словарь будет передаваться вдоль графа преобразований, и изменения будут видны в компонентах вниз по выводу (а также вверх). Давайте посмотрим на более очевидный пример того, чего вы *не должны* делать:

```python
def mutate_my_dict_and_yield() -> dict:
    d = {}
    for i in range(100):
        # Плохо! Не делайте этого!
        d['index'] = i
        yield d
```

Здесь один и тот же словарь выдаётся в каждой итерации, и его состояние, когда вызывается следующий компонент в цепочке, не определено (сколько изменений произошло с момента `yield`? Сложно сказать...).

Теперь давайте посмотрим, как сделать это правильно:

```python
def new_dicts_like_crazy(d):
    # Создание нового словаря правильно.
    return {
        **d,
        'foo': compute_something(),
        'bar': compute_anotherthing(),
    }

def new_dict_and_yield():
    for i in range(100):
        # Разный словарь каждый раз.
        yield {
            'index': i
        }
```

Спорим, вы думаете: «Да, но если я создам миллионы словарей...».

Допустим, мы выбрали противоположный путь и скопировали словарь вне преобразования (фактически, `это то, что мы сделали в предшественнике bonobo <https://github.com/rdcli/rdc.etl/blob/dev/rdc/etl/io/__init__.py#L187>`_). Это означает, что вы также создадите то же количество словарей, разница в том, что вы даже не заметите этого. Кроме того, это означает, что если вы хотите выдать один и тот же словарь 1 миллион раз, использование "чистого" подхода делает это эффективным (вы просто выдадите тот же объект 1 миллион раз), в то время как "безумное копирование" создаст 1 миллион идентичных объектов.

Использование словарей таким образом создаст много словарей, но также освободит их, как только все будущие компоненты, которые принимают этот словарь в качестве ввода, завершат работу. Кроме того, одна важная вещь, которую стоит отметить, — это то, что большинство примитивных структур данных в Python неизменяемы, поэтому создание нового словаря, конечно, создаст новую оболочку, но неизменённые объекты внутри не будут дублироваться.

Последнее, что копии, сделанные в "чистом" подходе, являются явными, и обычно явное лучше, чем неявное.
