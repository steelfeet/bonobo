# Часть 3: Работа с файлами

Вывод в консоль — это хорошо, но давайте будем серьёзны, реальный мир потребует от нас использования файлов или внешних сервисов.

Давайте посмотрим, как использовать несколько встроенных средств записи, а также локальные и удалённые файловые системы.

## Файловые системы

В |bonobo| доступ к файлам осуществляется в рамках сервиса **файловой системы** (объект `fs' FileSystem` <https://docs.pyfilesystem.org/en/latest/builtin.html>`_).

По умолчанию вы получите экземпляр локальной файловой системы, сопоставленной с текущим рабочим каталогом, как сервис `fs`. Вы узнаете больше о сервисах на следующем этапе, но пока давайте просто используем его.

## Запись в файлы

Чтобы записать в файл, нам нужно иметь открытый дескриптор файла, доступный в течение всего жизненного цикла преобразования.

Мы будем использовать контекстный процессор для этого. Контекстный процессор — это нечто очень похожее на :obj:`contextlib.contextmanager`, которое |bonobo| будет использовать для запуска логики настройки/очистки на объектах, которые должны иметь тот же жизненный цикл, что и выполнение задания.

Давайте напишем тот, который просто обрабатывает открытие и закрытие файла:

```python
def with_opened_file(self, context):
    with open('output.txt', 'w+') as f:
        yield f
```

Теперь нам нужно написать преобразование `writer` и применить этот контекстный процессор к нему:

```python
from bonobo.config import use_context_processor

@use_context_processor(with_opened_file)
def write_repr_to_file(f, *row):
    f.write(repr(row) + "\n")
```

Параметр `f` будет содержать значение, выданное контекстными процессорами, в порядке появления. Вы можете связать несколько контекстных процессоров. Чтобы узнать, как это реализовать, ознакомьтесь с гайдами |bonobo| в документации.

Обратите внимание, что декоратор :func:`bonobo.config.use_context_processor` изменит функцию на месте, но не изменит её поведение. Если вы хотите вызвать её вне контекста задания |bonobo|, это ваша ответственность — предоставить правильные параметры (и здесь — открытый файл).

Чтобы запустить это, измените последний этап в пайплайне в get_graph на write_repr_to_file:

```python
def get_graph(**options):
    graph = bonobo.Graph()
    graph.add_chain(
        extract_fablabs,
        bonobo.Limit(10),
        write_repr_to_file,
    )
    return graph
```

Теперь запустите tutorial.py и проверьте файл output.txt.

## Использование файловой системы

Мы открыли выходной файл, используя жёстко заданное имя файла и реализацию файловой системы. Написание гибких заданий включает возможность изменять цели загрузки во время выполнения, и |bonobo| предлагает использовать сервис `fs` для достижения этого с файлами.

Давайте перепишем наш контекстный процессор, чтобы использовать его.

```python
def with_opened_file(self, context):
    with context.get_service('fs').open('output.txt', 'w+') as f:
        yield f
```

Интерфейс меняется не сильно, но это небольшое изменение позволяет конечному пользователю изменять реализацию файловой системы во время выполнения, что отлично подходит для обработки разных окружений (локальная разработка, промежуточные серверы, продакшн, ...).

Обратите внимание, что |bonobo| предоставляет очень мало сервисов с реализацией по умолчанию (на самом деле, только `fs` и `http`), но вы можете определить все сервисы, которые хотите, в зависимости от вашей системы. Вы узнаете больше об этом в следующей главе руководства.

## Использование другой файловой системы

Чтобы изменить реализацию `fs`, вам нужно предоставить свою реализацию в словаре, возвращаемом `get_services()`.

Давайте запишем в удалённое расположение, которое будет корзиной Amazon S3. Сначала нам нужно установить драйвер:

```shell
pip install fs-s3fs
```

Затем просто предоставьте правильную корзину в :func:`bonobo.open_fs`:

```python
def get_services(**options):
    return {
        'fs': bonobo.open_fs('s3://bonobo-examples')
    }
```

> **Примечание**
>
> Вы должны предоставить корзину, для которой у вас есть разрешение на запись, и это ваша обязанность настроить ваши учетные данные Amazon таким образом, чтобы `boto` мог получить доступ к вашей учётной записи AWS.

## Использование встроенных средств записи

До этого момента и для лучшего понимания того, что происходит, мы реализовали средства записи сами.

|bonobo| содержит средства записи для различных стандартных форматов файлов, и вам, вероятно, лучше использовать встроенные средства записи.

Давайте используем экземпляр :obj:`bonobo.CsvWriter` вместо этого, заменив наше пользовательское преобразование в функции фабрики графа:

```python
def get_graph(**options):
    graph = bonobo.Graph()
    graph.add_chain(
        ...
        bonobo.CsvWriter('output.csv'),
    )
    return graph
```

## Чтение из файлов

Чтение из файлов выполняется с использованием той же логики, что и запись, за исключением того, что у вас, вероятно, будет только один вызов средства чтения. Вы можете прочитать файл, который мы только что написали, используя экземпляр :obj:`bonobo.CsvReader`:

```python
def get_graph(**options):
    graph = bonobo.Graph()
    graph.add_chain(
        bonobo.CsvReader('input.csv'),
        ...
    )
    return graph
```
