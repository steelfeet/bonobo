# Часть 2: Написание ETL-заданий

В |bonobo| ETL-задание — это граф с некоторой логикой для его выполнения, как файл, который мы создали в предыдущем разделе.

Вы можете узнать больше о структуре данных :class:`bonobo.Graph` и её свойствах в [гайде по графам](../guide/graphs.md).

## Сценарий

Давайте создадим пример приложения, цель которого будет интегрировать некоторые данные в различные системы.

Мы будем использовать набор открытых данных, содержащий все fablabs в мире.

Мы нормализуем эти данные, используя несколько различных правил, а затем запишем их куда-нибудь.

На этом этапе мы сосредоточимся на нормализации этих данных и выводе их в консоль. На следующих этапах мы расширим это для других целей, таких как файлы и базы данных.

## Настройка

Мы изменим файл `tutorial.py`, созданный на последнем этапе, для обработки этого нового сценария.

Сначала давайте удалим весь шаблонный код, чтобы он выглядел так:

```python
import bonobo


def get_graph(**options):
    graph = bonobo.Graph()
    return graph


def get_services(**options):
    return {}


if __name__ == '__main__':
    parser = bonobo.get_argument_parser()
    with bonobo.parse_args(parser) as options:
        bonobo.run(get_graph(**options), services=get_services(**options))
```

Ваше задание теперь содержит логику для выполнения пустого графа, и мы дополним его логикой нашего приложения.

## Чтение исходных данных

Давайте добавим простую цепочку в нашу функцию `get_graph(...)`, чтобы она читала из fablabs API открытых данных.

Набор исходных данных, который мы будем использовать, можно найти на [этом сайте](https://public-us.opendatasoft.com/explore/dataset/fablabs/).

Он лицензирован под `Public Domain`, что делает его идеальным для нашего примера.

> **Примечание**
>
> Существует модуль :mod:`bonobo.contrib.opendatasoft`, который упрощает чтение из API OpenDataSoft, включая пагинацию и ограничения, но для нашего руководства мы избежим этого и создадим его вручную.

Давайте напишем наш извлекающий узел:

```python
import requests

FABLABS_API_URL = 'https://public-us.opendatasoft.com/api/records/1.0/search/?dataset=fablabs&rows=1000'

def extract_fablabs():
    yield from requests.get(FABLABS_API_URL).json().get('records')
```

Этот извлекающий узел будет вызван один раз, запросит URL-адрес API, проанализирует его как JSON и выдаст элементы из списка "records" один за другим.

> **Примечание**
>
> Вы, вероятно, захотите сделать его немного более многословным в реальном приложении, чтобы обрабатывать всевозможные ошибки, которые могут произойти здесь. Что если сервер не работает? Что если он возвращает ответ, который не является JSON? Что если данные не в ожидаемом формате?
>
> Для простоты мы проигнорируем это здесь, но это те вопросы, которые у вас должны быть в голове при написании пайплайнов.

Чтобы протестировать наш пайплайн, давайте используем :class:`bonobo.Limit` и :class:`bonobo.PrettyPrinter` и изменим нашу функцию `get_graph(...)` соответствующим образом:

```python
import bonobo

def get_graph(**options):
    graph = bonobo.Graph()
    graph.add_chain(
        extract_fablabs,
        bonobo.Limit(10),
        bonobo.PrettyPrinter(),
    )
    return graph
```

Запуск этого задания должен вывести немного данных вместе с некоторой статистикой.

Сначала давайте посмотрим на статистику:

```shell
- extract_fablabs in=1 out=995 [done]
- Limit in=995 out=10 [done]
- PrettyPrinter in=10 out=10 [done]
```

Важно понимать, что мы извлекли всё (995 строк), прежде чем отбросить 99% набора данных.

Это нормально для отладки, но неэффективно.

> **Примечание**
>
> Вы всегда должны стараться ограничить количество данных как можно раньше, что часто означает не генерировать данные, которые вам не понадобятся в первую очередь. Здесь мы могли бы использовать параметр запроса `rows=` в URL-адресе API, чтобы не запрашивать данные, которые мы в любом случае отбросим.
