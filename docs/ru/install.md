# Установка

## Создайте ETL-проект

Сначала установите фреймворк:

```shell
$ pip install --upgrade bonobo
```

Создайте простое задание:

```shell
$ bonobo init my-etl.py
```

И запустим его для теста:

```shell
$ python my-etl.py
```

Поздравляем, вы запустили своё первое ETL-задание Bonobo.

Теперь вы можете перейти к [руководствам](tutorial/index.md).

> **Примечание**
>
> Часто лучше всего начать с одного файла, а затем перенести его в проект (который в Python должен находиться в пакете).
>
> Подробнее об этом вы можете прочитать в разделе [Упаковка](guide/packaging.md), вместе с указаниями о том, как перенести этот первый файл в существующий полнофункциональный Python-пакет.

## Другие варианты установки

### Установка из PyPI

Вы можете установить его напрямую из [Python Package Index](https://pypi.python.org/pypi/bonobo) (как мы сделали выше).

```shell
$ pip install bonobo
```

Для обновления существующей установки используйте `--upgrade`:

```shell
$ pip install --upgrade bonobo
```

### Установка из исходного кода

Если вы хотите установить невыпущенную версию, вы можете использовать git-URL с pip. Это полезно, когда вы используете bonobo как зависимость вашего кода и хотите попробовать форкнутую версию bonobo со своим программным обеспечением. Вы можете использовать строку `git+http` в файле `requirements.txt`. Однако лучший вариант для разработки bonobo — это редактируемая установка (см. ниже).

```shell
$ pip install git+https://github.com/python-bonobo/bonobo.git@develop#egg=bonobo
```

> **Примечание**
>
> Здесь мы используем ветку `develop`, которая является предстоящей невыпущенной минорной версией. Это способ "жить на острие", либо для тестирования вашей кодовой базы с будущим выпуском, либо для тестирования невыпущенных функций. Вы можете использовать эту технику для установки любой нужной ветки и даже ветки в собственном репозитории.

### Редактируемая установка

Если вы планируете вносить патчи в Bonobo, вам следует установить его как "редактируемый" пакет, что является действительно отличной функцией pip. Pip клонирует ваш репозиторий в исходный каталог и создаёт символическую ссылку на него в каталоге site-packages вашего интерпретатора Python.

```shell
$ pip install --editable git+https://github.com/python-bonobo/bonobo.git@develop#egg=bonobo
```

> **Примечание** Вы также можете использовать `-e`, сокращённую версию `--editable`.

> **Примечание** Ещё раз мы используем здесь `develop`. Новые функции должны идти в `develop`, а исправления ошибок могут идти в `master`.

Если вы не можете найти "исходный" каталог, попробуйте выполнить следующее:

```shell
$ python -c "import bonobo; print(bonobo.__path__)"
```

### Локальный клон

Другой вариант — иметь "локальную" редактируемую установку, что означает, что вы создаёте клон самостоятельно и делаете редактируемую установку из локального клона.

```shell
$ git clone git@github.com:python-bonobo/bonobo.git
$ cd bonobo
$ pip install --editable .
```

Вы можете разрабатывать в этом клоне, но, вероятно, захотите добавить свой собственный репозиторий, если хотите отправлять код обратно и делать pull-запросы. Обычно я называю git remote для основного репозитория bonobo "upstream", а свой собственный репозиторий — "origin".

```shell
$ git remote rename origin upstream
$ git remote add origin git@github.com:hartym/bonobo.git
$ git fetch --all
```

Конечно, замените моё имя пользователя GitHub на то, которое вы использовали для форка bonobo. Всё должно быть готово!

### Предварительные версии

Иногда доступны предварительные версии (например, перед крупным выпуском). По умолчанию pip не нацеливается на предварительные версии, чтобы избежать случайного обновления до потенциально нестабильной версии, но вы можете легко согласиться:

```shell
$ pip install --upgrade --pre bonobo
```

## Поддерживаемые платформы

### Linux, OSX и другие Unix

Набор тестов Bonobo непрерывно работает на Linux, и основные разработчики используют машины как OSX, так и Linux. Кроме того, ежедневно выполняются задания на производственных Linux-машинах, поэтому поддержка этих платформ должна быть вполне отличной.

Если вы используете какую-то экзотическую UNIX-машину, могут быть сюрпризы (хотя мы об этом ещё не знаем). Мы официально не поддерживаем эти платформы, но если вы сможете исправить проблемы в этих системах, мы будем рады интегрировать ваши патчи (при условии, что это протестировано как для существующих сред Linux, так и для ваших странных систем).

### Windows

Поддержка Windows корректна, так как несколько участников помогли нам протестировать и исправить особенности.

На платформе Windows могут оставаться мелкие проблемы, в основном из-за того, что bonobo не разрабатывался пользователями Windows.

Мы пытаемся это исправить, но доступная энергия для серьёзной поддержки Windows очень ограничена.

Если у вас есть опыт в этой области и вы готовы помочь, мы будем очень рады!
