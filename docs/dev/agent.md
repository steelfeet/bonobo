# KODA — Инструкционный контекст

## Обзор проекта

**Bonobo** — это ETL-фреймворк (Extract-Transform-Load) для Python 3.5+, предназначенный для потоковой обработки данных. Проект ориентирован на простоту использования и атомарность преобразований данных с помощью ориентированных графов из обычных Python-вызываемых объектов (функций, генераторов, итераторов).

### Основные особенности

- **Простота**: Использует обычные Python-объекты без сложного синтаксиса
- **Параллелизм**: Выполняет преобразования параллельно (по умолчанию на основе потоков)
- **Чистота кода**: Поощряет написание чистых, тестируемых преобразований
- **Графовая модель**: Ориентированные ациклические графы для определения пайплайнов
- **Расширяемость**: Модульная архитектура с поддержкой плагинов

### Архитектура

Основные компоненты:

- `bonobo/` — ядро фреймворка
  - `commands/` — CLI-команды (run, init, inspect, convert и др.)
  - `config/` — система конфигурации и внедрения зависимостей
  - `execution/` — логика выполнения графов
  - `nodes/` — встроенные узлы (CsvReader, JsonWriter, Filter, Limit и др.)
  - `structs/` — структуры данных (Graph, Bag и др.)
  - `contrib/` — расширения (Django, Jupyter, SQLAlchemy, Selenium)
- `tests/` — тестовый набор
- `docs/` — документация (исходники на английском, переведены на русский в `docs/ru/`)
   - `dev` - документация разработчика
      - issues.md - текущие задачи
      - agent.md - актуальное описание проекта для LLM
      - changelog.md - сделанные изменения и их обоснование

### Технологический стек

- **Язык**: Python 3.5+
- **Основные зависимости**:
  - `fs ~= 2.0` — абстракция файловых систем
  - `graphviz >= 0.8, < 0.9` — визуализация графов
  - `requests ~= 2.0` — HTTP-клиент
  - `jinja2 ~= 2.9` — шаблонизатор
  - `mondrian ~= 0.8` — логирование
  - `whistle ~= 1.0` — система плагинов
- **Тестирование**: pytest ~= 4.6, pytest-cov, pytest-timeout
- **Документация**: Sphinx 1.7
- **Форматирование**: yapf, isort, black

## Сборка и запуск

### Установка

```bash
# Базовая установка
pip install -e .

# Или через Makefile
make install

# С зависимостями для разработки
make install-dev

# С дополнительными зависимостями
make install-docker    # для Docker
make install-jupyter   # для Jupyter
make install-sqlalchemy  # для SQLAlchemy
```

### Запуск тестов

```bash
# Полный набор тестов с покрытием
make test

# Или напрямую pytest
pytest --capture=no --cov=bonobo --cov-report html tests

# Быстрый запуск без покрытия
pytest tests
```

### Форматирование кода

```bash
# Форматирование всего кода (требует black и isort)
make format

# Или вручную
black -l 120 .
isort -rc -o mondrian -o whistle -y .
```

### Сборка документации

```bash
# Сборка HTML-документации
make docs

# Или через sphinx-build
sphinx-build -b html docs docs/_build/html

# Автоматическая пересборка при изменениях
sphinx-autobuild docs /tmp/docs-build
```

### CLI-команды

```bash
# Запуск ETL-графа
bonobo run my_job.py

# Создание нового задания
bonobo init my_etl.py

# Инспекция графа (требует graphviz)
bonobo inspect --graph my_job.py | dot -Tpng -o graph.png

# Преобразование форматов файлов
bonobo convert -r csv input.csv -w json output.json

# Просмотр версии
bonobo version
```

## Правила разработки

### Стиль кодирования

- **Основной стандарт**: PEP8 с ограничением строки в **120 символов**
- **Форматирование**: Используется `yapf` с конфигурацией в `.style.yapf`
  - `based_on_style = pep8`
  - `column_limit = 120`
  - `coalesce_brackets = true`
  - `dedent_closing_brackets = true`
- **Сортировка импортов**: `isort` с конфигурацией в `.isort.cfg`
  - `line_length=120`
  - `known_first_party=bonobo`
  - `known_third_party=mondrian,whistle`
- **Альтернативное форматирование**: `black -l 120` (поддерживается в `make format`)

### Тестирование

- Все изменения должны сопровождаться тестами
- Используйте pytest для написания тестов
- Тесты находятся в директории `tests/`
- Покрытие кода должно поддерживаться на высоком уровне
- Для медленных тестов используйте декоратор `@pytest.mark.slow`

### Написание чистых преобразований

- Преобразования не должны модифицировать входные данные на месте
- Возвращайте новые объекты вместо изменения существующих
- Используйте генераторы для потоковой выдачи данных
- Избегайте побочных эффектов в преобразованиях

### Внедрение зависимостей

- Используйте декоратор `@use('service_name')` для функций
- Используйте `Service('service_name')` для классов
- Определяйте сервисы в функции `get_services()`
- Сервисы по умолчанию: `fs` (файловая система), `http` (HTTP-клиент)

### Конвенции именования

- **Преобразования (функции/экземпляры классов)**: `snake_case`
  ```python
  def process_row(row):
      return row

  filter_rows = Filter(...)
  ```

- **Фабрики и конфигурируемые классы**: `CamelCase`
  ```python
  class TransformData(Configurable):
      pass

  def CreateTransform(method):
      pass
  ```

### Документация

- Документация пишется на reStructuredText (.rst) в `docs/en/`
- Переводы на русский язык в `docs/ru/` в формате Markdown (.md)
- Используйте docstrings для всех публичных API
- Примеры кода должны быть рабочими и проверяться

### Контрибуция

## Специфические аспекты проекта

### Графы и узлы

- Графы — это ориентированные ациклические графы (DAG)
- Узлы — это любые вызываемые объекты Python
- Данные передаются через FIFO-очереди между узлами
- Поддерживаются разветвления (forks) и слияния (joins) потоков

### Стратегии выполнения

- По умолчанию: потоковая стратегия (ThreadStrategy)
- Каждый узел выполняется в отдельном потоке
- Поддерживаются стратегии на основе подпроцессов (для CPU-bound задач)

### Расширения

- **Django**: Интеграция через `bonobo.contrib.django.ETLCommand`
- **Jupyter**: Виджеты для визуализации выполнения в ноутбуках
- **SQLAlchemy**: Чтение/запись в SQL базы данных
- **Selenium**: Веб-скрапинг и автоматизация браузера

### Настройки

Настройки могут переопределяться через переменные окружения:

- `DEBUG` — режим отладки
- `QUIET` — тихий режим
- `PROFILE` — профилирование
- `LOGGING_LEVEL` — уровень логирования
- `IOFORMAT` — формат ввода/вывода (`kwargs` или `arg0`)

### Локализация

Документация переведена на русский язык в `docs/ru/`. При внесении изменений в документацию:

1. Обновите исходники в `docs/en/`
2. Соответствующим образом обновите переводы в `docs/ru/`
3. Сохраняйте структуру и форматирование
